# 安装时的视觉校验

分三层记录：模型宣称支持图片、当前agent工具能把图片送到该模型、实际图片题是否答对。前两层不是最后一层的替代。测试不能只问“你能看图吗”。

## 测试内容

make每次生成新的验证码、颜色顺序、指数与四面板排列。第一图检验实际输入和科学记号位置；第二图有正常、重叠、裁切面板。标准答案仅用于本地grade，不发给受测模型。不可用/超时/拒绝图片时记录失败或未核验，不猜。

agent用当前客户端已有的选模/委派和查看图片工具，将**这两张实际图片**送给便宜模型，以新上下文运行。只发PROMPT.txt要求及图像路径/图像附件，不发其他文件、标准答案和之前回答。原始模型回答存JSON：

```json
{
  "actual_model": "真实被调用的模型ID",
  "verification_code": "从图中读出",
  "leftmost_color": "red/blue/green",
  "exponent": 0,
  "panels": {"A": "clean/overlap/clipped", "B": "...", "C": "...", "D": "..."},
  "delivery": {"image_input_confirmed": true, "image_tool_evidence": ["第一图实际工具调用证据", "第二图实际工具调用证据"]}
}
```

示例的0不是答案。actual_model取平台实际调度记录，不能只抄用户期望的模型名。如果平台不暴露模型身份，不冒充已核验：标明无法确认，并选可确认的当前模型/人工辅助路径；配置状态仍要如实报告。图片内容通过文字重述给模型不算图片输入。

## 通过、回退和重测

grade检查新题、图片哈希、模型身份、实际图片输入证据及四组答案。通过记录绑定host、host_version、provider和review_model，保存在使用者自己的工作区。它是安装过程保留的工具证据，不是平台内部模型身份的密码学证明，也不是完整科学审稿能力认证。

若便宜模型只能处理文本，让它继续下载、命名、清单、Word脚本等步骤；视觉交给另外实际通过测试的模型，用户明确同意回退。finish同时保留便宜模型的实际测试结果和视觉审阅模型的通过结果，不标记“小模型视觉通过”。无人能看图时不进入ready状态。

models命令改模型/provider/客户端版本后恢复vision_pending。客户端升级、图片工具改变、模型别名/供应商路由改变时重新测试；客户端版本未知就不能自动检测其升级，需要agent主动检查。后续每次交付仍检查真实新增页和变化页，测试通过不能用来跳过页面目检。

探针不调用额外商业API，不要求保存密钥。测试图片是合成资料，不包含使用者论文或文档。仓库/Release不包含任何人的已通过记录，禁止把作者机器的测试结果当收件人的验收。
